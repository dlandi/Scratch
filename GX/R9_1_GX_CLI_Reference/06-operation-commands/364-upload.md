## 6.364. upload

#### Command Description

This command is used to upload files to a remote server. The desired content will be gathered, by automatically generating a single file, and then transferred. **File types** The supported \<filetype\> values for upload are:

- database : uploads a database snapshot
- debug-log : uploads logs for diagnostic troubleshooting (includes all other logs)
- krp: uploads Key Replacement Package
- local-certificate: uploadsexports the local certificate as a file from 1830 GX
- logs : uploads syslog files
- peer-certificate: uploadsexports the peer certificate as a file from 1830 GX
- pm-logs : uploads PM data logs
- fdr-log : upload FDR logs
- file : uploads any file from the file-system
- otdr-result : uploads otdr result
- script: uploads scripts
- swimage: uploads SW Image
- trusted-certificate: uploadsexports the trusted certificate(s) from 1830 GX

**Remote file destination** The destination can be provided in one of two ways:

<!-- page 1324 -->

1. based on a previously configured file-server and an associated remote path:

  - The path is optional for uploads.
  - If the path is not provided, the file-server initial-path is used with a system-defined filename.
  - If the path is relative (not starting with '/'), it will be concatenated with the file-server initial-path.
  - If the path is absolute (starting with '/'), the file-server initial-path is ignored

2. Based on a URL in the format: \<protocol\>://[\<user\>@]\<address\>[:\<port\>]/\<path\>/\<filename\>:

  - Protocol may be ftp, sftp, scp, http, https, file (non-secure protocol.
  - ftp, http - are only usable if secure-mode policy is disabled)
  - 'file' represents access to the local file system; this is particularly useful for mounted USB drives, which can still be used as a destination for uploads; when using a USB drive, no address/port/user/password is required. (!) Tip: use 'show usb' to see where a particular USB drive is mounted in.
  - Server port is optional; if not provided, the default port for that protocol is used
  - Address may be an ipv4/ipv6/hostname - For providing ipv6 addresses, use 'user@[ip:port]' (ex: scp://user@[2620:38:4::8:4000:238]/path/file)
  - Path represents an absolute path; it is not possible to use relative paths.
  - For sftp/ftp/scp, a username and a password need to be provided
  - The password can be provided inline with the command, or alternatively will be prompted to the user.

**Remote file name** The name of the uploaded file can be defined by the user or automatically generated by the system. If the path targets a directory (e.g. /path/ ), the filename is dynamically generated as: \<file-type\>\_\<ne-name\>\_\<timestamp\>.\<extension\> . If the path targets a specific filename (e.g. /path/file), the used has the ability to use some dynamic placeholders:

- %D - represents the timestamp at the time of the file upload, in format DD-MM-YYYY-hh.mm.ss
- %M - represents the NE name.
- %E - represents NE type (1830 GX G40; 1830 GX G30…).
- %X - XFR Type (database, logs, etc).
<!-- page 1325 -->
- %N - represents NE id.
- %L - represents DCN Loopback IP.

**Asynchronous Upload** The upload may be triggered as a background task with the -a flag (asynchronous). If so, the user can visualize the current state with the command  `show` `transfer-status filetype`. **Skip secure verification for Upload** The Upload may be triggered with -s flag. If so, HTTPS file transfers skip TLS verification and SCP/SFTP transfers skip ssh known host verification. If flag not set, verification is according to current security policy. **Rules for naming of the uploaded file**

1. If no file name is provided for the upload, the filename is auto-generated based on:

\<file-type\>\_\<ne-name\>\_\<timestamp\>.\<extension\> Example: `upload debug-log destination=scp://user@someserver//home/user Output:`

```
debug_log_GX_11-18-11-2020-19.07.48.tar.gz
```

2. If the file name is provided, the filename is used as is.

Example: `upload debug-log destination=scp://user@someserver.com//home/user/your_file_name.tar.gz card-1-1 Output :`

```
your_file_name.tar.gz
```

**Note:** Debug-entity is a mandatory parameter.

3. If the filename contains placeholders %m or %t , then those are replaced by network element name and timestamp respectively in the uploaded file name.

Example: `upload database destination=scp://user@someserver.com//home/user/%m_your_file_name_%t Output :`

```
NENAME_your_file_name_11-18-11-2020-19.34.48
```

**Generic file upload** By providing 'file' as file-type, any file can be uploaded to the file-system. The \<source\> parameter will define where the file is located. This parameter can be:

- a file-name only: uses default directory with the file-name
- a relative path: uses the default directory as starting path, plus relative path
- an absolute path: Absolute path for the user accessible directories can be used

It is necessary for the user to have write access to the source path for the download to succeed.

**Tip:** Use 'show transfer' to see what is the default storage directory.

For generic file transfer, no further activity occurs after download, so the 'unattended' flag will be ignored.

#### Command Syntax

```
upload [-a] [-s] [filetype=]<value> ([destination=]<value> | [file-server=]<value> [[path=]<value>]) [[source=]<value>] [debug-entity=]<value>
[password=]<value> [[period=]<value>] [[optional-content=]<value>[,<value>]*] [[log-file-list=]<value>[,<value>]*] [[start-time=]<value>]
[[db-instance=]<value>] [[db-passphrase=]<value>] [certificate-name=]<value>
```

<!-- page 1327 -->

**Note:** When users use the `upload` command to export certificates (local, peer, or trusted certificates), a specific certificate needs to be specified using **certificate-name** except for trusted-certificates, where the absence of a specific name implies that all trusted-certificates will be exported as a certificate bundle. Only the public part is exported. Private keys are not exported. The output files are in P7 pem format.

#### Examples

**Tip:** In synchronous file transfer mode, a textual progress bar is rendered live in the CLI during the transfer. In asynchronous file transfer mode, the download or upload operation is performed in the background; to check the progress, use the `show transfer-status` command.

This example shows how to upload a file:

```
upload filetype=file destination=https://iartifactory.infinera.com/artifactory/in-thanos-local/sop/2.1.0/test_sanket/RSA_2048.pem
 source=/storage/RSA_2048.pem
```

This example shows how to upload logs to a specific URL, with system defined filename:

```
upload logs scp://user@138.111.200.1//home/user/
```

This example shows how to upload logs to USB drive, with system defined filename:

```
upload logs file://media/5-U1/
```

This example shows how to upload 15min PM logs to serverX:

```
upload pm-logs serverX /home/tom/ period=pm-15min
```

This example shows how to upload all available OTDR result files for subcard 1-5.1:

```
upload otdr-result serverX card-1-5.1
```

This example shows how to upload all available OTDR result files for port 1-5.1-1:

```
upload otdr-result serverX port-1-5.1-1
```

This example shows how to export the trusted certificate **myRoot2** to the destination:

```
upload trusted-certificate destination=sftp://jz@100.113.83.14:/home/jz/demos/trusted2.pem certificate-name=myRoot2
```

This example shows how to export all the trusted certificates to the destination:

<!-- page 1331 -->

```
upload trusted-certificate destination=sftp://jz@100.113.83.14:/home/jz/demos/all.pem
```

This example shows how to export the local certificate **myLeaf** to the destination:

```
upload local-certificate destination=sftp://jz@100.113.83.14:/home/jz/demos/leaf.pem certificate-name=myLeaf
```
